Dezibot Bluetooth Mesh

This repository is an ESP-IDF project (built with PlatformIO) for experimenting with Bluetooth Mesh on an ESP32-S3.

  • Bluetooth host initialization runs via NimBLE.
  • The mesh functionality is broken down into reusable modules under lib/ and documented using Doxygen.

Contribution / State of the art

The project is based on typical ESP-IDF BLE mesh examples, but goes one step further towards a “continuable” project:

  • Clear module separation (bluetooth, client, provisioner) instead of monolithic example code.
  • Small API functions for sending frequent generic model messages.
  • Doxygen documentation for the modules used, including build/tooling configuration.

Project structure

  • src/main.c: Entry point/example application.
  • lib/: Reusable BLE mesh modules and public headers.
  • platformio.ini: Fixes platform/board/framework.
  • Doxyfile: Doxygen configuration.
  • docs/: Generated documentation.

Modules in lib/

Bluetooth

Provide BLE host stack so that BLE Mesh can run.

How it works:

  • Initializes NimBLE (nimble_port_init()).
  • Registers host callbacks (ble_hs_cfg.reset_cb, ble_hs_cfg.sync_cb, Storage Callback).
  • Starts the NimBLE host task under FreeRTOS (nimble_port_freertos_init()).
  • Derives a mesh device UUID from the controller address (ble_mesh_get_dev_uuid()).

Client

Send model messages to other nodes as a BLE mesh client node.

How it works:

  • Initializes the mesh stack in the client role setup (ble_mesh_client_init()).
  • Provides helpers to send frequent generic messages (OnOff, Level, Power Level, Location, User Property).
  • The target is typically a unicast address of an already provisioned node.

Provisioner

Find unprovisioned devices, provision them, and then configure them initially using the Config Client.

How it works:

  • Event/callback-based process: Unprovisioned advertisements are received and added to the provisioning queue.
  • After successful provisioning, UUID->Unicast/Element info is stored and queried via the Config Client, e.g., Composition Data.
  • Optionally, AppKeys can be added/bound to prepare the node for model communication.

Build

Build with PlatformIO (ESP-IDF Framework):

pio run -e esp32s3usbotg

Flash and monitor:

pio run -e esp32s3usbotg -t upload
pio device monitor

Doxygen

Generating the HTML documentation:

doxygen Doxyfile

Then open docs/html/index.html.

Note on configuration: The current Doxyfile is designed for “header-only” documentation (public API from lib/*.h) so that the file list does not redundantly map .c and .h twice. If you also want to document internal static functions from .c, set FILE_PATTERNS including *.c in Doxyfile again and set EXTRACT_STATIC = YES.
